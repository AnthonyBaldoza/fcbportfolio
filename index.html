01 · About

Building software end to end

I got into full-stack development the way most engineers do — by wanting to build something specific enough that no template fit. My most-used project is a chess tournament pairing system: a console-based Swiss pairing algorithm I rebuilt into a proper Spring Boot REST API with a live, board-themed frontend, because manually pairing players round after round doesn't scale.

That instinct carried into everything else I build: a Pokédex REST API in ASP.NET Core with real input validation, a full e-commerce and inventory system built with a team, and a handful of browser games where I learned to debug things that only break at 60 frames a second.

I like the full stack specifically — the discipline of a well-shaped database, an API contract that makes sense, and a frontend that doesn't get in the way.
